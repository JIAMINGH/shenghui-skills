# 外贸案例与复盘

## 使用范围
适用于学员理解方法论、跨行业迁移及复盘。

## 核心原则
复盘时标明证据来自项目记录、教学示例还是后续测试。对公开案例使用获准披露的资料，客户身份与联系方式保存在私人业务项目。

## 项目案例：六语自行车批发站

### 已记录的项目实践

- **任务。** 让批发商与 OEM/ODM 买家用当地语言看车型、了解工厂及定制服务，并能提交采购需求。项目已有六语内容，需要梳理可发布版本、联系入口和事件记录。
- **交付。** 将六语预生成页面、表单声明、路由、图片和脚本整理为独立发布目录。产品列表、详情、工厂与联系页按语种提供。六种语言各有隐私政策页，写明询盘、WhatsApp、语言偏好与追踪用途。
- **遇到的问题。** 同一仓库的 React 源代码是较早的双语版，直接重建会覆盖已经核对过的六语发布目录。之后维护时先识别六语版本来源，保留可回退的发布包，检查打包后的资源路径大小写与入口引用。
- **核查证据。** 项目日志记载，较早版本发布包与线上抽样页面及资源比对通过。后续六语发布包核对了归档、站点地图与资源引用。本地发布文件可查到联系页、表单声明、各语言隐私页和追踪脚本。日志和代码证明的范围以对应版本为准。
- **待复核。** 当前材料未闭合某条真实社媒内容到询盘、报价或订单的归因，也缺少本次线上收件、接待和 Meta 事件到账的实测记录。

### 用这个项目演练从内容到跟进

以下为沿实际站点结构设计的**演练**。

1. 以西语批发商为目标，写一条解决选款或采购配置问题的短视频。把 CTA 对准西语产品页或联系页，并标记本条内容的来源。
2. 从手机打开链接，用虚拟采购需求测试。核对表单实际收到的型号、用途、批量与市场，再检查已配置的事件。如果选 WhatsApp，则核对消息确实到达接待端。
3. 接待人记录入口、采购任务、线索状态和下次行动。客户有配置疑问时，按 [WhatsApp 聊单流程](13-whatsapp.md#用-ai-做一页目标语销售资料) 准备真实资料，再问这轮最影响采购判断的问题。
4. 复盘时用可追溯记录找断点。访问多但没有到达记录，先测入口。收到的需求多但不匹配，检查内容和表单。已经匹配但报价停滞，回看客户缺的证据或条件。无法对应来源的询盘保留未知。

## 教学情景

### 情景 A：自行车工厂老板 IP
问题：只展示成品难以让采购商识别真实生产能力。尝试：负责人出镜讲产品与可定制范围，配合产线、展厅和多语内容。验证：对比同类内容带来的有效 B 端线索，不以播放量推导订单。

### 情景 B：百货供应链整店输出
问题：SKU 多，客户难理解一站式供货优势。尝试：按采购场景展示组合、仓储与打包能力，引导客户提交品类、数量与目的地。验证：匹配采购需求、报价率与供应稳定性。

### 情景 C：工程机械或建材（假设示例）
问题：客户高度重视规格、质量及售后。尝试：技术负责人讲解工况、检测与交付流程，站点承接技术资料和询价。验证：有效项目数量、合规证书与实际可服务区域。

## 执行 SOP
复盘顺序：原问题→假设→执行→可核查证据→有效线索和成交结果→可能混杂因素→可迁移的机制→下一轮测试。不得把单案例结论绝对化。

## 交付标准
输出：情景、可迁移原则、行业适配调整、验证指标；明确真实自述/假设/已验证状态。
