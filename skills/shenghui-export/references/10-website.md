# B2B独立站建设

## 使用范围
适用于 AI 建站、询盘网站结构、多语与部署。

## 核心原则
- 独立站核心是让 B 端买家理解工厂、产品和合作方式并提交询盘，不是默认做零售商城。
- 页面建议：首页、产品分类、产品详情、工厂/产线、质量、OEM/ODM、联系；必要时加案例/FAQ。
- 真实参数、真实图片、真实认证与可核查交付信息优先。CTA 可为询价、WhatsApp、邮箱，字段最少且能有效筛选。
- AI 建站工具、Netlify、Cloudflare 等是可选实现；按需求选部署与图片存储，不能把服务商功能或价格写成永久固定。

## 执行 SOP
1. 收集品牌、产品、参数、优势、目标语言、联系信息及公开授权素材。
2. 构建信息架构与各页内容，先做移动端可读、易联系。
3. 实现表单验证、成功/失败提示、反垃圾、隐私告知；仅经授权设置分析/广告追踪。
4. 测试不同屏幕、多语链接、图片、表单发送、邮箱/WA 跳转与 404。
5. 部署前保护密钥，确认域名/HTTPS、备份、维护责任；未实际部署不得说已上线。

## 社媒到询盘的验收

1. 从目标语言的社媒主页、广告或视频入口打开实际链接，用手机确认页面语言、主推产品、关键规格和联系入口。用不同入口分别记录，来源无法对应时保留未知。
2. 在获准测试的环境，用带编号的虚拟采购需求测试表单。记录选用语言、关键字段、提交结果、后台记录、通知和接待人。通过 WhatsApp 咨询时，核对消息到达、接待人和是否能继续询问需求。
3. 需要 Meta 追踪时，沿 [广告线索验收](09-meta-ads.md#验收三种咨询入口) 查成功事件与去重，记录范围和结果。
4. 上线前确认交付物对应哪一版源代码、发布目录和托管项目。手动上传时核对上传根目录、资源路径大小写和在线版本，再检查根域名、www 与 HTTPS。记录问题、负责人、完成时间和复测方式。

对照 [六语自行车批发站案例](15-cases.md#项目案例六语自行车批发站)，说明哪些已从本地文件核验，哪些还需在线接收端验收。
